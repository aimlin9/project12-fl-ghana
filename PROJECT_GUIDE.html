1The Big Picture

Your project predicts which students are "at-risk" of dropping out or failing, across three Ghanaian schools, without any school sharing its raw student data. This is the core innovation.

The Problem: Student data is sensitive and protected by privacy laws. Schools cannot legally send student records to a central server. But a model trained on only one school's data won't generalise well to other schools.
The Solution — Federated Learning: Each school trains a local AI model on its own data. Only the model update (not the data) is sent to the server. The server combines all updates into a better global model. No raw data ever leaves the school.

On top of Federated Learning, the project adds two extra layers of security:

  • Differential Privacy (DP-SGD) — adds mathematical noise during training so the model update cannot be reverse-engineered to reveal individual student records
  • Paillier Homomorphic Encryption — encrypts the model update before it is sent, so even the server never sees the raw update values

4The AI Model — client/model.py

The prediction model is a Multi-Layer Perceptron (MLP) — a feedforward neural network with three layers:

Input (8 features)
      ↓
Linear(8 → 64) + ReLU activation
      ↓
Linear(64 → 32) + ReLU activation
      ↓
Linear(32 → 1) + Sigmoid activation
      ↓
Output: probability (0.0 – 1.0)
If output ≥ 0.5 → student is AT-RISK
If output < 0.5 → student is NOT at-risk

Training Details

  • Loss function: BCELoss (Binary Cross-Entropy) — standard for binary classification
  • Optimizer: Adam with learning rate 0.01
  • Local epochs: 3 per federated round (each school trains for 3 full passes over its data)
  • Batch size: 32 students per gradient step
  • Total parameters: 2,689 trainable weights
Why this model? It is small enough to train on a laptop CPU in seconds per round, while still being a genuine neural network. The focus of the project is the federated learning infrastructure, not the model architecture.

Evaluation Metrics

MetricWhat it measuresTarget
F1-score (macro)Balance of precision and recall across both classesWithin 5pp of baseline
AccuracyFraction of correct predictionsHigher is better
AUC-ROCModel's ability to rank at-risk students above safe onesCloser to 1.0 is better

5Privacy Protection — security/privacy.py

What is Differential Privacy?

Differential Privacy (DP) is a mathematical guarantee that says: "The output of this algorithm is nearly the same whether or not any single person's data is included."

In practice, it works by adding carefully calibrated random noise to the gradients during training. This is called DP-SGD (Differentially Private Stochastic Gradient Descent).

How it Works in the Code

Standard training:
  gradient = loss.backward()
  optimizer.step(gradient)

DP-SGD training:
  1. Compute per-sample gradients (one gradient per student)
  2. Clip each gradient to max_norm = 1.0
     (prevents any one student from dominating the update)
  3. Add Gaussian noise scaled by noise_multiplier = 1.1
  4. Average the noisy clipped gradients
  5. optimizer.step(noisy_gradient)

Privacy Budget — Epsilon (ε)

Epsilon (ε) is the privacy budget. It measures how much privacy is spent.

Lower ε = stronger privacy guarantee (but usually lower accuracy)
Higher ε = weaker privacy guarantee (but usually higher accuracy)

The project targets ε ≤ 3.0 per round with δ = 1×10⁻⁵

Key Parameters

ParameterValueMeaning
noise_multiplier (σ)1.1Amount of noise added. Higher = more private
max_grad_norm1.0Maximum gradient size. Clips outliers
delta (δ)1×10⁻⁵Probability of privacy failure. Must be very small
Implementation library: Opacus 1.4 by Meta (Facebook). It wraps the PyTorch model in a GradSampleModule that automatically computes per-sample gradients efficiently.

6Encryption — security/crypto.py

What is Paillier Homomorphic Encryption?

Homomorphic encryption allows computations to be performed on encrypted data without decrypting it first. Paillier is a partial homomorphic encryption scheme that supports addition of encrypted values.

Normal encryption:
  Encrypt(5) + Encrypt(3) requires decryption first

Paillier encryption:
  Encrypt(5) ⊕ Encrypt(3) = Encrypt(8)   ← addition works on ciphertext!
  Decrypt(Encrypt(8)) = 8                 ← correct result

Why This Matters for Federated Learning

Without encryption: the server receives each school's model update in plaintext and could potentially analyse it to learn about students.

With Paillier encryption: the server receives encrypted updates, performs the weighted average while encrypted, and only decrypts the final combined result. Individual school updates are never visible to the server.

The Math — Weighted FedAvg in Encrypted Domain

School alpha has 480 students, beta has 440, gamma has 400.
Total = 1320 students.

Weight_alpha = 480/1320 = 0.364
Weight_beta  = 440/1320 = 0.333
Weight_gamma = 400/1320 = 0.303

Server computes (all encrypted):
  result = Encrypt(update_alpha) × 0.364
         + Encrypt(update_beta)  × 0.333
         + Encrypt(update_gamma) × 0.303

One decryption gives the correct weighted average.

7The FL Client — client/client.py

This is the code that runs on each school's computer. It is a Flower NumPyClient — a standard interface that Flower uses to communicate with clients.

The fit() Method — Training Phase

def fit(self, parameters, config):
    # 1. Check if school is toggled offline
    if get_client_status(school) == "Offline":
        return [], 0, {}

    # 2. Load the global model weights from server
    set_flat_weights(self.model, parameters)
    old_weights = get_flat_weights(self.model)

    # 3. Train locally with DP-SGD (3 epochs)
    for epoch in range(local_epochs):
        for X_batch, y_batch in train_loader:
            optimizer.zero_grad()
            outputs = model(X_batch)
            loss = criterion(outputs, y_batch)
            loss.backward()
            optimizer.step()   # DP noise added here by Opacus

    # 4. Compute the update (delta)
    new_weights = get_flat_weights(self.model)
    update = new_weights - old_weights

    # 5. Encrypt the update with Paillier
    encrypted_update = encrypt_weights(public_key, update)

    # 6. Send encrypted update + metrics back to server
    return parameters, num_samples, {
        "school_name": self.school_name,
        "encrypted_update": serialize(encrypted_update),
        "training_latency": elapsed_time,
        "epsilon": privacy_budget_spent,
    }

The evaluate() Method — Evaluation Phase

After each round of aggregation, the server sends the updated global model back. Each school evaluates it on its local test set (20% of its data) and reports F1, accuracy, and AUC-ROC back to the server.

8The FL Server Strategy — server/strategy.py

PaillierFedAvg Class

This is a custom implementation of the FedAvg algorithm that works with Paillier encrypted updates. It extends Flower's Strategy base class and overrides four methods:

Logging and Audit Trail

After every round, two records are written:

  • logs/fl_metrics.db — SQLite table with round_id, node_id, F1, loss, accuracy, latency, comm_mb, epsilon for every school every round

A Python dictionary called telemetry_data is shared between the strategy and the FastAPI server. The strategy writes to it after every round; the API reads it and sends it to the React dashboard every 3 seconds.

How the Simulation is Started

1. Dashboard sends POST /api/start
2. FastAPI checks port 8088 is free
3. Starts run_fl_simulation() as a background task
4. run_fl_simulation():
   a. Creates PaillierFedAvg strategy
   b. Starts Flower gRPC server on port 8088 (separate thread)
   c. Waits for port 8088 to be ready
   d. Starts one client thread per online school
   e. Waits for Flower server to finish all rounds
   f. Marks simulation as complete
Why threads? The Flower server and all school clients run in the same Python process but in separate threads. This simulates a real distributed system on a single machine for demonstration purposes.

12How a Full Round Works — End-to-End Flow

SERVER: Generates 512-bit Paillier key pair (once, Round 1 only)
↓
SERVER → ALL SCHOOLS: Sends global model weights + public key
↓
EACH SCHOOL: Receives global model, loads weights into local MLP
↓
EACH SCHOOL: Trains for 3 epochs with DP-SGD (Opacus adds noise to gradients)
↓
EACH SCHOOL: Computes update = new_weights − old_weights (2,689 numbers)
↓
EACH SCHOOL: Encrypts update with Paillier public key → 2,689 ciphertexts
↓
ALL SCHOOLS → SERVER: Send encrypted updates + metrics (F1, epsilon, latency)
↓
SERVER: Multiplies each encrypted update by its FedAvg weight (n_i / total)
↓
SERVER: Adds all weighted encrypted updates homomorphically (no decryption needed)
↓
SERVER: Decrypts once → gets weighted average model update
↓
SERVER: Adds update to global model: global = global + avg_update
↓
SERVER → ALL SCHOOLS: Sends updated global model for evaluation
↓
EACH SCHOOL: Evaluates on its 20% test set → reports F1, accuracy, AUC-ROC
↓
SERVER: Logs metrics to fl_metrics.db + crypto_audit.jsonl
↓
DASHBOARD: Polls /api/telemetry → updates charts and cards
↓
Repeat for next round…

13Likely Exam / Presentation Questions & Answers

Q: What is federated learning and why did you use it?
Federated learning is a machine learning approach where a model is trained across multiple devices or servers without sharing raw data. We used it because student data is sensitive and protected by privacy regulations. Each Ghanaian school cannot legally send student records to a central server, but with federated learning, only model updates (not data) are shared, so the schools can collaboratively build a better model while keeping student data local.
Q: What is differential privacy and how does it protect students?
Differential Privacy (DP) adds carefully calibrated mathematical noise to the model gradients during training. This provides a formal mathematical guarantee: the model update looks almost the same whether or not any individual student's data was included. Even if an attacker intercepts the model update, they cannot determine which specific student's record contributed to it. We use the Opacus library with a noise multiplier of σ=1.1 and clip gradients to max norm 1.0.
Q: What is Paillier encryption and why is it used here?
Paillier is a partially homomorphic encryption scheme. Its key property is that you can ADD two encrypted numbers together without decrypting them. We use this so the server can compute the weighted average of all school model updates while they remain encrypted. The server only decrypts the final combined result, so it never sees any individual school's raw model update. This adds a second layer of protection beyond differential privacy.
Q: What is FedAvg and how does your system implement it?
FedAvg (Federated Averaging) is the aggregation algorithm that combines multiple clients' model updates into one global model. Each client's update is weighted by how many training samples it contributed: weight_i = n_i / total_samples. Our implementation, PaillierFedAvg, applies these weights inside the encrypted domain using Paillier's scalar multiplication property before the homomorphic sum. This means the weighting and aggregation happen without decryption.
Q: What is the baseline and why does it matter?
The centralised baseline is what you get if you ignore privacy completely and train one model on all three schools' data combined. We train this using scripts/train_baseline.py. Our federated model should reach within 5 percentage points (5pp) of this baseline F1-score. This proves that the federated approach, with all its privacy protections, is nearly as accurate as the privacy-violating centralised approach.
Q: What is the non-IID problem and how does your project demonstrate it?
IID means "identically and independently distributed." In standard machine learning, all data is assumed to come from the same distribution. In federated learning, each client has its own data that may be very different. School_alpha has only 1.5% at-risk students while school_gamma has 54.8%. This is a non-IID distribution. Our project deliberately creates this scenario to show that FedAvg can still produce a useful global model despite these differences.
Q: What is epsilon (ε) in differential privacy?
Epsilon is the privacy budget — a measure of how much privacy is spent. Lower ε means stronger privacy. A value of ε=1 means the model update reveals almost nothing about any individual. Higher ε means weaker guarantees. Our privacy-accuracy sweep shows that as ε decreases (stronger privacy, higher noise), F1-score also decreases slightly — this is the fundamental privacy-accuracy tradeoff. The project targets ε ≤ 3.0 per round.
Q: Why does the dashboard show the Flower framework?
Flower (flwr) is the federated learning framework we use to handle the communication between the server and school clients. It provides the gRPC communication protocol, the client manager, the round scheduling, and the Strategy interface that we override with our PaillierFedAvg implementation. Flower runs on port 8088 while our FastAPI dashboard API runs on port 8000.
Q: What happens if a school goes offline during training?
This is the node dropout scenario we demonstrate live. When a school is toggled offline via the dashboard, its client thread does not connect to the Flower server for that round. The server's configure_fit() method uses client_manager.num_available() to sample only however many clients are actually connected, with a minimum of 1. Training continues with the remaining schools. The offline school's last-known status is preserved. This shows the resilience of federated learning to network failures.
